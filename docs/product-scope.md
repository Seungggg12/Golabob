# 골라밥 MVP 제품 범위

## 1. 제품 정의

골라밥은 사용자가 회식 조건을 등록하면 주변 식당 사장님이 맞춤 오퍼를 제안하고, 사용자가 오퍼를 선택해 단체 예약을 확정하는 역제안형 회식 매칭 플랫폼이다. 승인 식당의 일반 예약과 원격 웨이팅도 함께 제공한다.

## 2. 핵심 사용자

| 역할 | 목표 | 주요 행동 |
| --- | --- | --- |
| 예약자(`user`) | 조건에 맞는 회식 장소를 빠르게 확정한다 | 조건 등록, 오퍼 비교, 오퍼 선택, 예약 확인·취소 |
| 사장님(`owner`) | 비는 시간대에 단체 손님을 유치한다 | 회식 요청 탐색, 식당 조건에 맞는 오퍼 작성·관리, 예약 확인·취소 |
| 관리자(`admin`) | 신뢰할 수 있는 식당이 운영되게 한다 | 식당 승인·정지, 운영 정책 관리 |

모든 계정은 `user`로 가입한다. 현재 MVP에서는 사용자가 마이페이지에서 사장님 전환을 신청하면 즉시 `owner` 역할을 추가한다. 한 계정은 예약자와 사장님 모드를 전환할 수 있으며, 사업자 심사와 관리자 승인은 후속 단계에서 도입한다.

## 3. MVP 핵심 흐름

1. 사용자가 날짜, 시간, 인원, 지역, 1인 예산, 메뉴와 필수 조건을 입력해 회식 요청을 등록한다.
2. 승인된 식당을 가진 사장님이 모집 중인 요청을 조회한다.
3. 사장님이 가격, 메뉴, 혜택, 좌석, 가능 시간과 메시지를 포함한 오퍼를 보낸다.
4. 사용자가 본인 요청에 도착한 오퍼를 비교한다.
5. 사용자가 오퍼 하나를 선택한다.
6. 플랫폼이 선택 오퍼, 나머지 오퍼, 회식 요청과 예약을 하나의 트랜잭션으로 확정한다.
7. 사용자와 사장님이 예약 내역을 조회하고 필요한 경우 사유를 입력해 취소한다.

일반 예약 흐름에서는 사용자가 승인된 식당을 직접 선택해 날짜·시간·인원을 입력하고 예약을 확정한다. 두 예약 방식은 같은 예약 내역과 취소·완료·리뷰 정책을 사용한다.

원격 웨이팅 흐름에서는 사용자가 웨이팅 접수 중인 식당에 인원과 연락처를 등록하고 대기 순번을 확인한다. 사장님은 순서대로 호출하고 착석·취소·노쇼 상태를 처리한다.

## 4. MVP 포함 범위

- 이름·이메일·휴대전화·필수 약관 동의를 포함한 회원가입과 로그인
- 사용자 계정의 다중 역할 및 역할 전환
- 마이페이지 사장님 전환 신청과 즉시 역할 부여
- 식당 등록, 관리자 승인, 사장님 본인 식당 관리
- 회식 요청 등록·조회·조건부 수정·취소·만료
- 모집 중인 회식 요청의 사장님 조회
- 승인된 본인 식당을 통한 오퍼 등록·조회·조건부 수정·취소·만료
- 사용자 본인 요청에 도착한 오퍼 비교
- 오퍼 선택과 예약 확정의 원자적 처리
- 사용자·사장님의 예약 조회와 사유 기반 취소
- 승인된 식당의 일반 예약 등록
- 원격 웨이팅 등록, 대기 순번 조회, 고객 호출, 착석·취소·노쇼 처리
- 주요 상태 변경 이력과 수행 주체 기록
- 완료된 예약에 대한 리뷰 작성·수정·삭제

## 5. MVP 제외 범위

- 결제, 예약금, 환불, 정산
- 실시간 채팅과 전화 중계
- 쿠폰, 포인트, 등급, 광고 상품
- AI 식당 추천과 자동 오퍼 생성
- 식당별 복수 관리자와 직원 권한
- 여러 지점을 묶는 프랜차이즈 관리
- 외부 지도·POS·예약 서비스 연동
- 예상 대기시간 AI 예측과 테이블 자동 배치
- 운영자용 고급 통계와 자동 제재

## 6. 확정된 운영 정책

| 주제 | MVP 정책 |
| --- | --- |
| 사장님 역할 | 마이페이지에서 전환 신청 시 `owner` 역할을 즉시 부여한다. 사업자 심사와 관리자 승인은 후속 도입한다 |
| 결제 | 결제와 예약금 없이 플랫폼 내 예약 확정까지만 제공한다 |
| 식당 소유 | 식당마다 대표 owner 한 명만 허용하며 owner 한 명은 여러 식당을 가질 수 있다 |
| 오퍼 선택 | 하나를 선택하면 같은 요청의 나머지 대기 오퍼를 자동 거절한다 |
| 요청 수정 | `open` 상태이고 아직 유효한 오퍼가 없을 때만 허용한다 |
| 오퍼 수정 | `pending` 상태이고 원 요청이 `open`일 때만 허용한다 |
| 취소 | 사용자와 사장님 모두 예약 시작 전 취소할 수 있으며 사유와 수행 주체를 기록한다 |
| 만료 | 요청 마감 시각과 오퍼 만료 시각을 기준으로 시스템이 만료 처리한다 |
| 웨이팅 | 식당이 접수를 열고 사용자는 식당별 활성 웨이팅 하나만 등록하며 호출 제한 시간 초과 시 노쇼 처리한다 |

## 7. MVP 완료 기준

- 다른 사용자의 요청·오퍼·예약에 접근할 수 없다.
- 승인되지 않은 계정이나 식당은 오퍼를 보낼 수 없다.
- 한 요청에서 예약은 최대 하나만 생성된다.
- 일반 예약과 역제안 예약을 예약 유형으로 구분하고 동일한 소유권 검증을 적용한다.
- 동시 웨이팅 등록에도 식당별 대기 번호가 중복되지 않고 순서가 보존된다.
- 동시 선택 요청이 발생해도 오퍼 하나만 선택되고 예약 하나만 생성된다.
- 상태 변경과 취소 사유를 사용자·사장님·관리자가 확인할 수 있다.
- Web과 Mobile에서 동일한 API 계약으로 핵심 흐름을 완료할 수 있다.

## 8. MVP 이후 검토 사항

- 예약금과 취소 수수료 정책
- 식당 직원 초대와 세부 권한
- 알림 채널과 발송 실패 재처리
- 사용자·식당 신고 및 분쟁 처리
- 지역 검색과 거리 기반 요청 노출
- 개인정보 보관 기간과 탈퇴 데이터 처리
